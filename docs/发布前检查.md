## GitHub 与容器验证

- 已从 GitHub 远程仓库全新克隆，使用 Node.js 24 执行依赖安装、类型/格式、162 项单元/集成、36 项原型、前后端构建和完整 Chrome/Chromium/WebKit 回归，212 项通过、1 项 WebKit CDP 输入场景跳过。
- 远程 Linux runner 上类型、格式、单元测试和构建均通过；隔离 Docker job 通过通用镜像构建、生产空库保护、拒绝开发登录、Passkey/恢复码、临时数据保存，以及备份至新卷后内容/认证摘要与登录复验。
- 首轮/第二轮远程性能门槛检查曾失败：Linux WebKit 编辑样本超过 100ms，第二轮 Chromium 也有单次超过目标。没有将这些结果当作性能达标。
- 现将共享 CI runner 的性能用例用于保留原始样本、100ms 目标是否达到及基本完成性检查；非 CI 本机回归仍执行 100ms 目标。功能回归和容器检查继续阻断失败；当前远程最终结果见 GitHub Actions。
- Issues 和私下漏洞报告已启用，Discussions 关闭。

## 仍需在实际部署环境验收

- 千节点编辑 100ms 目标尚不能视为所有 Linux 云 runner 或用户设备都达标；性能数据需在固定硬件/浏览器下比较。
- 真实设备输入法、Passkey、公网双端编辑和自己的数据备份恢复仍需人工验收；CI 演练使用虚拟认证器和隔离生成数据。
- Docker CI 覆盖应用容器和命名卷恢复，不代替自己的真实域名、DNS、HTTPS 证书、反向代理和主机权限验收。
- 扫描工具不能保证发现所有敏感信息或未知漏洞；未来公开变更仍需重复审查。
