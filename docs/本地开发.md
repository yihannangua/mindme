# 本地开发

推荐 Node.js 24 和 npm。Node.js 后端使用内置 `node:sqlite`；锁文件用于复现依赖，`package.json` 的 `private: true` 仅防止误发布到 npm，不影响开源。

## 纯前端

```bash
npm ci
npm run dev
```

打开 `http://localhost:5173`。没有认证 API 时使用本地空间，无需账号。启动命令默认监听所有网卡，需要仅本机访问可追加 `--host 127.0.0.1`。

## 完整 Node 后端

```bash
cp .env.example .env
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

将输出填入 `.env` 的 `SESSION_SECRET`，保留 `NODE_ENV=development`、`AUTH_MODE=passkey`、`PUBLIC_ORIGIN=http://localhost:3180`。不要将随机值写进 Git 或工单。

```bash
npm run build
npm run build:server
node --env-file=.env dist-server/cli.js passkey-setup --fresh
node --env-file=.env dist-server/index.js
```

打开 `http://localhost:3180`，用首次设置令牌完成 Passkey 注册，下载/抄录恢复码到独立安全位置。`--fresh` 只允许空库；令牌过期且尚未登记时，可对已初始化空间运行不带 `--fresh` 的 `passkey-setup` 重新签发。已有 Passkey 的空间不再开放首次设置。

前端与 API 由同一 Node 服务提供，修改代码后重新构建并重启。Vite 模式独立提供本地空间，并未配置跨域代理。

## 常用检查

```bash
npm run check
npm run build
npm run build:server
npm run test:prototype
npx playwright install chromium webkit
npm run test:e2e:ci
npm run test:node
```

浏览器测试使用 `.wrangler/` 下的临时 SQLite；不要把 `MINDME_TEST_DATABASE` 指向自己的正式数据库。端到端端口分别为 4173、8792、8793，运行前应空闲。

## 历史兼容 Worker

`workers/index.ts`、`workers/space-object/` 和 `wrangler.jsonc` 保留旧入口。本地调试可使用 `npm run dev:worker`，Worker 集成回归为 `npm run test:cloud`，打包预检为 `npm run build:worker`。这一路径暂不提供完整云端部署支持。

Worker 的 Google 认证需要自行配置客户端 ID、准入邮箱和独立会话密钥，使用被忽略的 `.dev.vars`；开发认证只能在受限本地环境使用。默认配置不绑定个人域名，历史 Worker 的部署命令需要用户主动配置自己的云账号。
