# 腾讯云发布工具

发布包只从当前公开 `main` 的完整 SHA 制作。工具会核对 GitHub push CI 的仓库、main SHA、运行 ID、最新 attempt 和必需 job；从该 SHA 的白名单源码干净检出构建，输出 `release.tar.gz`、SHA-256 与 `release-source.json`。包内不允许出现环境文件、SQLite、生产数据、知识库或凭据。

## 本地命令

在 Node.js 24、已安装依赖、Gitleaks 可用的公开仓库根目录执行。SHA 和 CI run 需要从 GitHub 已完成的 `main` push 检查页面取得，不能使用 PR 的 head SHA 或仍在运行的检查。

```bash
npm ci
npm run package:tencent -- --sha 完整的40位SHA --ci-run 成功的CI运行ID
npm run verify:tencent -- --sha 完整的40位SHA --ci-run 成功的CI运行ID --package release-artifacts/完整SHA/release.tar.gz --sha256 包SHA256
```

包目录使用独占创建，重复构建不会静默覆盖旧产物。保存完整 SHA、CI run 和单独核验的包 SHA-256。

## 服务器只读预检

`deploy:tencent` 和 `rollback:tencent` 默认 `--mode plan`，只读检查 `current`、运行容器镜像引用、服务器私有环境文件权限及数据库 `quick_check`。必须提供可信 SSH host key、私有 SSH key、正式配置路径、数据目录、容器名、预期 current 和旧镜像引用。配置文件路径必须位于包和镜像之外，工具不打印其内容。

## 显式应用

只有在已确认维护窗口、隔离演练与备份恢复证据、schema 兼容性和唯一操作人之后，才可显式传 `--mode apply --maintenance confirmed`。远端通过 flock 阻止并发发布；部署前重新核对 current 和运行镜像、验证包清单/摘要、构建带来源标签的镜像，并创建权限为 `0600` 的 SQLite 一致性备份。切换失败时恢复旧应用并把 `current` 原子切回旧 release。回滚只切换到指定保留的应用 release，不还原数据库，确保候选期间的新写入不丢失。

`npm run test:docker` 会调用 `scripts/release/rehearsal.mjs`，在随机临时目录和 Compose 项目中直接执行远端 runner：先备份，再恢复到独立卷，分别用候选/原应用读取并逐表核对结构与内容，候选运行期写入后再应用回滚并确认写入仍在。演练包带 `rehearsalOnly` 标记，远端 runner 拒绝其用于生产。

当前本地工作树尚未提交，容器隔离演练未在 GitHub runner 执行，因此本工具尚未取得最终 CI 与完整隔离演练证据，不得用于生产 `apply`。合并工具后，必须以最终 `main` SHA 的成功 CI 确认容器 job 中的配置隔离、独立卷恢复、应用回滚和新写入保留均通过，才可重新评估生产资格。

任何 SHA、CI、摘要、私有配置、备份、兼容性或身份校验失败都必须停止。该工具不执行 `passkey-setup --fresh`，不删除数据卷，不覆盖生产 SQLite。生产部署必须另有授权，本说明不授予部署权限。
