# 数据协议与备份边界

当前应用源码版本为 `0.1.8`，内容与同步数据采用 `schemaVersion: 1`。实际字段以 `src/domain/types.ts`、`src/sync/protocol.ts` 和 `shared/state.ts` 为准。

## 浏览器数据

- IndexedDB 数据库 `mindme.v1` 保存空间内容、编辑草稿、待同步 outbox、设备序号和服务端基线。
- 内容保存与队列更新使用事务；无法确认保存时保留内存内容及错误状态。
- localStorage 中的画布、选择和分区偏好只作用于当前浏览器，不属于云端协议或内容备份。
- 本浏览器同一时刻仅允许一个页面写入空间，其他页面需显式接管。

## 增量同步

操作以稳定 ID 去重，服务端分配事件序号；客户端保留已确认基线。不同字段可合并，删除记录阻止过期修改复活；身份不一致时暂停同步。时间估计包含不确定范围，无法安全合并的内容保留为草稿供处理。

历史版本新增使用单条 `history-add`，服务端仍兼容旧的完整 `history` 字段。超过增量边界会回退完整空间，不能据此假定大型历史始终低内存。当前模型最多保留 10 个内容历史版本；回收站按 30 天到期处理。

节点可选样式字段 `fontFamily`、`fontSize` 和 `backgroundColor` 分别参与字段级同步、撤销及内容 JSON 备份。未设置或为 null 时使用默认外观；字号为 10–48 的整数，背景色为六位十六进制颜色，字体为 `sans`、`serif` 或 `mono`。实际显示字体取决于设备的字体回退。

兼容性注意：旧版服务端不接受新增样式字段的增量操作，旧版客户端也不能直接应用这些字段的增量事件。新版服务端将含样式变更的节点事件转换为旧版可读取的节点快照；新版客户端在提交样式前确认服务器能力，旧服务端或回滚期间保留本机待同步队列。若能力检查和提交之间发生回滚，服务端可能记住拒绝的操作 ID，新客户端会为该操作生成新 ID 并保留队列重试。已有不含样式字段的节点数据可由新版读取，不需要数据库结构迁移。正式升级或回滚仍需完成独立备份恢复及混版验证，保全旧设备待同步数据。

## 内容 JSON 与完整备份

| 方式                         | 覆盖内容                                              | 不覆盖/限制                                                  |
| ---------------------------- | ----------------------------------------------------- | ------------------------------------------------------------ |
| 界面 JSON 导出               | 单图或空间脑图内容及标签                              | 不包含全部服务端历史、回收站、队列、认证信息；导入生成新副本 |
| `mindme-server` v1 迁移 JSON | 状态、序号、去重、删除记录及会话等迁移字段            | 不含 Passkey 凭据；Passkey 空间禁用此导出方式                |
| SQLite 一致性备份            | 服务端完整数据库，包括 Passkey 和恢复码哈希等认证记录 | 不包含浏览器未同步内容和服务器环境密钥                       |

Passkey 部署应使用 `node dist-server/cli.js backup 目标路径` 创建一致性备份；运行时必须使用正确的 `DATABASE_PATH`。完整恢复还需要与原空间匹配的环境密钥和站点来源。保留浏览器尚未同步内容的独立备份。

## 运行接口

- `GET /api/health`、`GET /api/ready`：进程健康和空间就绪状态。
- `/auth/session`、`/auth/passkey/*`、`/auth/recovery/*`、`/auth/refresh`：认证、设置及会话续期。
- `/api/sync`、WebSocket：内容同步，要求有效会话及相应来源/CSRF 校验。

首次设置令牌为短期能力凭据，恢复码一次性消费；不得进入公开附件。未知数据版本和非空目标导入会拒绝，避免以旧格式覆盖已有数据。
